Date: 2026-08-16. Machine: this Mac (this-mac), Darwin 25.5.0, home LAN
(en0 192.0.2.64). Tailscale 1.102.2 standalone. NordVPN IKEv2 profile
generated by `bin/nord-ikev2-profile.sh` for server `de1545.nordvpn.com`,
installed via System Settings (user-scoped, profile id
`ie.boboco.vpn-switch.nordvpn-ikev2`). The NordVPN **app** was disconnected
throughout; its tunnel never appeared (no `10.5.x` utun, no `100.64.0.2`
resolver — verified before each phase).

Everything below is copied from the measurements recorded on the bead as
they were taken. Anything not measured is marked **UNMEASURED**.

Nord's IKEv2 server pushes Nord's documented public DNS. The `100.64.0.2`
resolver that black-holed every DNS query when the app was up is installed
by the app's NordLynx tunnel extension, not by Nord's network. With IKEv2
there is nothing inside `100.64.0.0/10` for Tailscale's route to capture.

## 4. Programmatic control — what works and what does not

Verified dead ends (do not retry):

- `scutil --nc` cannot address the config at all: not by display name, not
  by the profile PayloadUUID, not by any of the five configuration UUIDs in
  `/Library/Preferences/com.apple.networkextension.plist` (each → "No
  service"), not while connected. `scutil --nc` enumerates
  SystemConfiguration services; a profile-installed personal VPN is a
  NetworkExtension configuration. Scope (user vs device) does not change
  this. `scutil --nc list` also hides *disabled* configs, which is why the
  freshly-installed profile looked "not created" until toggled once.
- `profiles install` is removed on this macOS ("profiles tool no longer
  supports installs. Use System Settings").
- UI-scripting System Settings > VPN: the pane opens but System Events sees
  an empty accessibility tree for the SwiftUI content. Abandoned after a
  bounded attempt.

The working handle: **Shortcuts "Set VPN"** (Apple-documented, macOS 13.3+),
run from scripts via `shortcuts run "NordVPN On"` / `"NordVPN Off"`.
Implemented in `lib/nord-ctl.sh` and `bin/vpn-ctl.sh`. Two facts shape it:

- `shortcuts run` **returns 0 even when the shortcut does not exist**
  (stderr: "Couldn't find shortcut"). The library therefore checks
  `shortcuts list` first (exit 3 with instructions if missing) and, after
  invoking, verifies *reality* — `ipsec0` inet present/absent and the
  `103.86.x` resolvers — with a bounded wait. The CLI's exit code is never
  trusted.
- The `shortcuts` CLI can `run` and `sign` but not create or import; the two
  shortcuts must be created once by hand (≈30 s; exact steps in
  `nord-ikev2-setup.md` § "Shortcuts for NordVPN control"). Until then,
  `vpn-ctl.sh nord on|off` exits 3; `status` and Tailscale control work
  regardless.

Not pursued: having the menu bar app own the IKEv2 configuration itself via
`NEVPNManager` (real-time `NEVPNStatus`, no polling). It needs the Personal
VPN entitlement and therefore an Apple Developer Program membership — a
cost/packaging decision for the operator, not something to do unattended.

## 5. State detection

`nord_state` is derived from reality, never from a status API:
`ipsec0` with an inet address and/or resolver `103.86.96.100`/`103.86.99.100`
⇒ IKEv2 up; a `utun` with `10.5.x` and/or resolver `100.64.0.2` ⇒ the
**app** tunnel (unsupported alongside Tailscale). Shared implementation:
`lib/nord-detect.sh`, used by `dns-verify.sh`, `dns-watch.sh`,
`dns-snapshot.sh`, `nord-ctl.sh`, `vpn-ctl.sh`.
